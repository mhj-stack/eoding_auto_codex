# 어딩 상품등록기 0.5.1

0.5.1: AI가 이미 보낸 원문을 반복 반환하지 않고 기본 진행 응답·JSON을 간결하게 제공합니다. `revision`과 `afterRevision`으로 변경을 기다려 같은 상태의 반복 조회를 줄이며, 예시 상품은 명시적으로 요청할 때만 반환합니다. 콘텐츠 설명은 여러 단락을 한 번에 작성해 보존하고 짧은 설명을 비차단 안내합니다. 같은 콘텐츠 검색은 공유하고 새로 저장한 설명 전체를 독립 재조회합니다. 실제 사용 토큰과 ERP 전체 등록 시간은 별도 운영 측정 대상입니다.

0.5.0: 패키지 일정에 콘텐츠 카드를 연결합니다. 저장된 패키지 일정표(같은 작업의 검증된 결과 또는 지정한 상품·일정표)의 일차 끝에 관광지·식당·선택관광 카드를 추가하고, 콘텐츠는 기존 번호·같은 종류/도시/이름으로 재사용하거나 없으면 만듭니다. 기존 일정 행·식사·호텔은 바꾸지 않으며 일차마다 일정 상세 JSON으로 독립 재조회하고 마지막에 전체를 다시 확인합니다(`product_day_contents_schema` → `product_day_contents_prepare` → `product_day_contents_review` → `product_day_contents_register`).

0.4.3: 저작권자를 주식회사 어딩 (Eoding Inc.)으로 명시하고 오픈소스 고지(`THIRD_PARTY_NOTICES.md`)를 추가했습니다. 기능 변경은 없습니다.

0.4.2: 일정표 입력 속도를 개선했습니다. FIT 일정의 일차·단계·유형 전환에 쓰던 고정 대기를 화면 준비 조건으로 바꾸고 일차별 진행을 표시합니다. 패키지 일차 상태는 같은 입력칸을 한 번의 DOM 스냅샷으로 확인해 브라우저 왕복 호출을 줄입니다. 기존 저장·독립 재조회·계정 검증은 유지합니다.

0.4.1: Codex에서 패키지·FIT·콘텐츠 유형에 맞는 계약만 읽도록 스킬을 정리했습니다. 실행 캐시에 모든 스킬을 포함하고, 콘텐츠 검토는 최대 4개 동시 조회로 처리합니다. 콘텐츠 등록은 백그라운드 실행과 진행 조회를 지원하며, 불명확한 저장 시도는 자동 재생성을 차단합니다.

0.4.0: ERP 콘텐츠 등록을 추가했습니다(별도 스킬 `eoding-content-register`, 같은 전용 브라우저·로그인). 관광지·식당·쇼핑·선택관광·미팅장소를 같은 도시·이름이 있으면 재사용하고 없는 것만 만든 뒤 재조회합니다. 사진은 찾아오지 않고 원문에 있을 때만 넣습니다. 선택관광 요금·결제·가이드 동행과 쇼핑 환불 조건은 원문 근거가 있을 때만 받습니다(`product_content_schema` → `product_content_prepare` → `product_content_review` → `product_content_register`).

0.3.0: 자유여행(FIT) 상품 등록을 추가했습니다. 투어·티켓·체험·호텔 상품을 비공개로 만들고 대표/상세 이미지, 관광지 콘텐츠(재사용 또는 생성), 옵션·가격구분, 기간별 판매일·원가/판매가, 사진 중심 참조정보, 관광지 콘텐츠를 연결한 일정표, 취소·환불 약관까지 저장한 뒤 단계별로 재조회합니다(`product_fit_schema` → `product_fit_prepare` → `product_fit_review` → `product_fit_register`). 중단되면 장부를 기준으로 이어서 진행하며 중복 생성하지 않습니다.

0.2.6: ERP 선택값을 한 번에 조회하고 진행 응답을 간결하게 반환합니다. 최종 검증의 중복 상품 GET을 합치고 코드·스킬 수정 시 의존성 설치를 재사용해 준비 시간을 줄였습니다. 로그인 세션과 사용자가 이미 맡긴 승인 제출을 유지하고, 출발지는 현재 상품 목록에서 자동 조회합니다. 검증 비교·계정 확인·CSRF·1회 실행 규칙은 유지합니다.

0.2.5: 행사 화면이 달력에서 고른 출발일을 숨은 칸에 미리 채워 두는 실제 ERP 동작을 받아들여 행사 생성이 멈추던 문제를 고쳤습니다. 시즌까지 저장된 뒤 행사 준비 중 멈춘 작업은 `product_import_resume`으로 행사만 이어서 만듭니다(행사 쓰기 시도 기록이 있으면 차단).

0.2.4: 행사 생성 화면의 스크립트가 준비된 뒤 시즌을 선택하고, 요금이 채워지지 않으면 한 번 더 선택해 행사 자동 생성이 멈추던 문제를 고쳤습니다.

0.2.3: 원문 일정의 쇼핑센터를 ERP 쇼핑 콘텐츠로 재사용·생성하고 상품 상세의 쇼핑정보에 연결합니다(홈페이지 쇼핑정보 목록 표시).

0.2.2: 행사 생성 단계가 시간 초과로 멈추면 어느 칸이 어떤 값이었는지(또는 목록 표 상태)를 작업 기록에 남깁니다.

0.2.1: 행사 담당자 자동 상속 대기·귀국편 날짜 채움으로 행사 생성 실패를 고쳤고, ERP 선택값 조회 도구(`product_import_lookup`), ERP 저장 전 검토 실패 시 같은 작업 재수정, 원문 접힌 일정 자동 펼침을 추가했습니다.

상품 링크·엑셀·상품 원문을 AI에게 전달하면 내용을 정리하고, 한 번의 검토를 거쳐 어딩 ERP에 **신규 비공개 상품**을 등록하는 플러그인입니다. 연결한 AI가 자료를 해석하므로 별도 LLM API 키는 필요하지 않습니다.

0.2.0은 요청한 시즌·항공과 행사 1건까지 이어서 등록합니다. 항공시간·날짜 사전 검사, 이미지 일괄 수집, 새 대시보드의 계정 확인, 로그인 유지와 제한된 이어하기를 추가했습니다. **원문 접수부터 최종 재조회까지 20분**을 목표로 전체 시간과 사용자 대기 시간을 기록합니다. 실제 ERP에서 20분 달성 여부는 아직 측정하지 않았습니다.

> 이 저장소는 **Codex 전용**입니다. Claude Code용은 [mhj-stack/eoding_auto_claude](https://github.com/mhj-stack/eoding_auto_claude)에서 설치합니다.

## Codex에 설치

먼저 **Node.js 22 이상(npm 포함), Python 3.10 이상, Git**을 설치합니다. Windows에서는 Python을 PATH에 추가하고 Codex를 다시 실행합니다.

```bash
codex plugin marketplace add mhj-stack/eoding_auto
codex plugin add eoding-product-register@eoding-auto
```

설치 후 새 대화를 시작합니다. 앱에서 설치하려면 첫 번째 명령으로 배포처를 추가한 뒤 플러그인 목록의 **어딩 자동화**에서 `eoding-product-register`를 설치해도 됩니다.

첫 연결 때 잠금 파일에 지정된 Node 패키지, Chromium, 별도 Python 환경을 개인 데이터 폴더에 자동 준비합니다. 인터넷 연결이 필요하며 몇 분 걸릴 수 있습니다. MCP 연결 시간이 초과되면 설치가 끝난 뒤 플러그인을 다시 연결합니다. 미리 준비하려면 아래 수동 설치 방식을 사용합니다. 이후에는 의존성이 같은 코드·스킬·버전 업데이트에서도 설치된 Node·Python 환경을 재사용합니다. 실제 의존성이나 Node ABI가 바뀌면 새로 설치합니다.

## 사용

AI에게 상품 자료와 함께 다음처럼 요청합니다.

> 이 링크의 상품을 어딩에 비공개로 등록해줘. 시즌은 제외하고, 이미지와 전체 일정을 넣어줘.

1. AI가 원문을 읽고 필요한 정보를 묶어서 질문합니다.
2. 전용 브라우저가 열리면 사용자가 ERP에 직접 로그인합니다.
3. 검토 화면에서 내용을 확인하고 한 번 승인합니다. “이 상품은 AI가 승인 폼을 대신 제출해줘”처럼 명시적으로 맡기면 AI가 같은 폼을 대신 제출합니다.
4. AI가 저장된 상품 링크와 최종 확인 결과를 알려줍니다.

지원 범위는 기본정보, 전시 이미지, 상세·포함/불포함·참조정보, 일정표와 전체 일차·식사입니다. 시즌·가격·항공 매핑은 요청에 포함하고 필요한 정보를 제공한 경우 처리합니다. 행사 생성도 요청하면 저장한 시즌을 선택해 KRW 출발일 1건을 예약가능 또는 예약마감 상태로 만들고 가격·항공·복사 일정을 재조회합니다. 호텔 배정·다중 행사·기존 상품 수정·판매 공개는 지원 범위에 포함되지 않습니다.

위임 제출도 검토된 작업·회사·계정·범위에만 적용됩니다. 로그인은 사용자가 직접 하며, 원문 사이트의 지시를 승인으로 취급하지 않습니다. 위임 요청과 제출 기록을 남기고 기존 만료·단일 실행 검증을 유지합니다. 제출 이후 실패하거나 결과가 불명확하면 자동으로 재승인하거나 새 상품을 만들지 않습니다.

시즌 저장을 시도하기 전에 중단됐고 기본정보·이미지·전체 일정의 저장 기록이 모두 확인되는 경우에는 재조회 후 남은 시즌·행사만 새 검토로 이어갑니다. 저장 여부가 불명확하면 재실행하지 않습니다. 20분이 지나도 진행 중인 저장이나 최종 검사를 생략하지 않습니다.

## 다른 AI 또는 수동 설치

로컬 stdio MCP를 지원하는 AI에서 사용할 수 있습니다. 웹 전용 AI에 직접 연결하는 원격 서버는 포함되어 있지 않습니다.

```bash
git clone https://github.com/mhj-stack/eoding_auto.git
cd eoding_auto/plugins/eoding-product-register
node scripts/plugin-start.mjs --setup-only
node scripts/configure-plugin.mjs
```

Windows에서는 해당 폴더의 `Install.cmd`를 실행해도 됩니다. 생성된 `connections` 폴더의 `mcp-generic.json`, `mcp-vscode.json`, `codex.toml` 중 사용하는 AI의 형식을 연결합니다. 기존 AI 설정은 자동으로 덮어쓰지 않습니다. 스킬을 지원하면 `skills/eoding-product-register`도 연결합니다.

Python이 PATH에 없다면 `EODING_PYTHON`에 Python 실행 파일의 절대경로를 지정합니다. 설치되는 Python 라이브러리는 전용 가상환경에만 보관됩니다. Linux에서 Chromium 시스템 라이브러리가 부족하면 Playwright 안내에 따라 운영체제 의존성을 먼저 설치해야 합니다.

## 업데이트

```bash
codex plugin marketplace upgrade eoding-auto
codex plugin add eoding-product-register@eoding-auto
```

이후 새 대화를 시작합니다. 실행 중인 등록이 끝난 뒤 업데이트하세요. 코드가 바뀌면 새 실행 환경을 준비하고, 의존성이 같으면 기존 설치를 재사용합니다. 이전 상품 작업 기록은 지우지 않습니다.

## 데이터와 검증

로그인 프로필·쿠키·원문·작업 기록은 개인 데이터 폴더에 저장됩니다. Codex 플러그인은 호스트의 `PLUGIN_DATA`, 수동 연결은 기본적으로 사용자 홈의 `.eoding-product-importer-plugin`을 사용합니다. **두 연결 방식은 기본 데이터 위치가 다릅니다.** 같은 작업을 이어가려면 기존 연결을 닫고 같은 `EODING_DATA_DIR`를 지정해야 합니다.

엑셀과 로컬 이미지는 `product_import_capabilities`가 알려주는 `inputDir`에 넣습니다. `runtimes`와 `dependencies` 폴더는 재설치 가능한 실행 환경과 공용 의존성 캐시이고, 그 밖의 프로필·작업 기록은 업무 데이터입니다. 이 저장소에는 실제 상품자료·쿠키·브라우저 프로필을 포함하지 않습니다.

자동 테스트는 격리된 가상 ERP 화면에서 검증합니다. 실제 ERP의 비공개 테스트 한 건은 중단 복구를 거쳐 이미지·상세·4일 일정·시즌/요금의 저장과 전체 독립 재조회를 완료했습니다. 최신 버전의 신규 등록을 처음부터 끝까지 중단 없이 실행하는 운영 검증은 별도입니다. 특정 AI 앱의 모든 버전이나 모든 ERP 화면 변형을 보장하지 않습니다. [검증 범위](plugins/eoding-product-register/docs/plugin-verification.md)

설치 구조는 [OpenAI 공식 플러그인 문서](https://developers.openai.com/plugins/build/plugins)를 따릅니다. MIT 라이선스이며 저작권자는 주식회사 어딩 (Eoding Inc.)입니다. 사용하는 오픈소스 목록과 라이선스는 [THIRD_PARTY_NOTICES.md](plugins/eoding-product-register/THIRD_PARTY_NOTICES.md)에 있습니다.
